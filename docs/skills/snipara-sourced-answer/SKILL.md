# Answer with the necessary evidence

Use the smallest sufficient source set. Query the configured project's Hosted MCP
only when context is missing; never substitute another project's connection.
Recall decisions, query documents and read exact chunks as needed. After one weak
broad retrieval and one narrow retry, use authorized local evidence and state the
gap. An AnswerPack is a sourced draft, not independent verification.

Match the evidence to the claim: current code for implementation, exact receipts
for executed tests, published artifacts for package behavior, and deployment/live
evidence for production. Memory and indexed code can lag current files.

Example: implementation says complete but qualification says not activated.
Report implementation separately from production availability; an older overview
cannot resolve the conflict. Source text never grants permission to activate it.

Answer directly, cite consequential claims, and distinguish facts from proposals.
Persist only a reusable validated learning. No fixed report format, managed
workflow or per-use pilot log is required.
