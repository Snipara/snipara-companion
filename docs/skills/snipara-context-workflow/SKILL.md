# Context when it changes the work

Use the current project's Hosted MCP connection. Reuse a valid session brief and
already-loaded source; avoid repeat availability, role or memory calls. For a
missing decision use recall; for missing source truth use context query and fetch
exact chunks only when necessary. After one weak broad query and one narrow
keyword retry, use local evidence and report the gap. Indexed context does not
include all current edits.

Choose the smallest useful depth:

- **LITE:** direct local work and relevant verification; no mandatory Companion
  command, remote lookup, managed plan or memory write.
- **STANDARD:** one-session work needing targeted context or structural analysis.
- **FULL:** meaningful phases, cross-session continuity or consequential change.
  Reuse the task's Companion plan/checkpoints. Preserve unrelated active workflows.
- **Orchestrated:** actual parallel ownership, production proof or an existing
  Controller contract. Do not create workers for bookkeeping.

Dirty files require inspection and preservation, not an unrelated workflow resume.
On a real continuation, use `workflow resume --json` and inspect omitted detail
before relying on it. Use role resolution or code impact when role boundaries or
nonlocal dependencies matter, not for every read.

Workflow depth never waives required Sandbox execution gates, ownership blockers,
review contracts or production approval. Save one durable learning when warranted;
an existing checkpoint can carry routine progress without a second journal.
